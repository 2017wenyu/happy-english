## 发音终版 v3：环境自适应方案（15:05）

- 发现问题：downloadFile方案在开发者工具可以，真机无声音（真机严格校验downloadFile域名）
- 根本认知：SSL 10001 错误是**开发者工具特有问题**，真机系统证书完整，InnerAudioContext直连URL完全没问题
- 最终方案：`wx.getSystemInfoSync().platform === 'devtools'` 判断环境
  - 开发者工具 → downloadFile下载临时文件再播（绕过工具SSL bug）
  - 真机 → 直接 InnerAudioContext 加载URL（SSL无问题，最简单）

## 发音终版：downloadFile + 本地播放（14:50）

- `InnerAudioContext` 直连外网 URL 会触发开发者工具 SSL 校验报错（errCode 10001）
- 解决方案：`wx.downloadFile` 先把有道 MP3 下到临时路径，再用 `InnerAudioContext` 播放本地文件
- `downloadFile` 走微信自己的下载通道，不受同一套 SSL 校验限制
- 加了内存级缓存 `_cache`，同一个词只下载一次
- 用户已在微信后台同时配置了 `request` 和 `downloadFile` 两个合法域名

## 优化：发音方案改回有道词典TTS + 修复GC问题（14:20）

- `project.config.json` 中 `urlCheck:false` 已关闭域名校验，有道词典URL在开发阶段可正常访问
- 发音无效的根本原因：`InnerAudioContext` 实例是局部变量，函数返回后即被GC回收，音频还没播完就停了

- `flashcard.js` / `spelling.js` 均已按此方案修复
